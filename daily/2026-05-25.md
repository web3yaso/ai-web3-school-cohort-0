## 1. EOA、智能账户和多签账户权限对比

今天整理了一篇任务文档：

[Week 1 Web3 任务：比较 EOA、智能账户和多签账户](../tasks/2026-05-25-account-permission-comparison.md)

这篇文档重点比较了三类账户的权限边界：

- EOA：由单个私钥直接控制，谁掌握私钥谁就能发起交易。
- 智能账户：由智能合约规则控制，可以支持恢复、限额、自动化、session key、批量交易等策略。
- 多签账户：一种典型智能账户，需要多个 owner 达到签名门槛后才能执行交易，适合团队资金和高价值资产管理。

今天比较后最大的理解是：账户类型的差异不只是“钱包形式不同”，而是背后的风险分配不同。

EOA 的发起和批准几乎合并在一次签名里，所以使用简单，但私钥是单点风险。智能账户把权限变成可编程规则，可以更灵活地限制 agent 或用户操作，但也引入合约和配置风险。多签账户把批准权分散给多个 signer，降低单点失效，但需要处理协作、threshold 和 owner 管理问题。

我觉得最关键的问题是：

> 谁能发起交易，谁能批准交易，谁在出错时承担风险。

这对之后理解 AI agent wallet、Safe、Cobo CAW、ERC-4337、EIP-7702 都很有帮助。

## 2. 回看 Agent Memory 分享

今天还回看了 5.25 的分享：

Long-term Memory for AI Agents：如何让 Agent 拥有持续上下文与长期一致性

笔记链接：

https://x.com/AgentEconCN/status/2059122899781321012

这次分享让我重新理解了 Agent Memory 的价值：memory 不是简单把聊天记录存起来，而是让 agent 在长期任务中保留可复用的上下文、偏好、历史决策和反馈。

如果没有 memory，agent 每次都像从零开始，只能依赖当前 prompt。  
如果有设计良好的 memory，agent 可以逐渐理解用户的目标、风险偏好、常用工作流和已经做过的事情。

但 memory 也会带来新的问题：

- 存什么：不是所有上下文都值得长期保存。
- 谁能读：memory 可能包含敏感信息。
- 怎么更新：错误记忆如果长期保留，会持续影响 agent 判断。
- 怎么删除：用户需要能撤销、修改或清空记忆。
- 怎么验证：agent 不能把旧记忆当成永远正确的事实。

这和 Web3 的身份、权限、审计也能联系起来。未来如果 agent 参与钱包操作、任务执行或支付流程，memory 里保存的不只是偏好，还可能影响权限判断和风险控制。

## 今日收获

今天的两个主题其实有一个共同点：都在讨论“长期控制权”。

账户权限模型讨论的是资产和链上动作的控制权：谁能发起、谁能批准、谁承担风险。  
Agent Memory 讨论的是上下文和决策连续性的控制权：agent 记住什么、如何使用记忆、记忆是否会影响未来行动。

如果把两者放在一起看，未来 AI × Web3 的核心问题之一可能是：

> 一个拥有长期记忆的 agent，在被授予链上权限后，如何被安全地限制、审计和纠正？

这也是后面做 agent wallet、agent payment、agent commerce 或 Safe execution 时必须回答的问题。
