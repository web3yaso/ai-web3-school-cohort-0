# ERC-8183 vs x402：核心对比

## 一句话总结

**x402 解决“访问资源时怎么自动付费”；ERC-8183 解决“完成任务后怎么托管、验收、结算”。**

---

## 核心区别

| 维度 | x402 | ERC-8183 |
|---|---|---|
| 核心对象 | HTTP 请求 / API / 内容访问 | Job / Task / 服务交付 |
| 主要问题 | “你要访问这个资源，先付钱” | “你完成这个任务，验收后付款” |
| 支付模式 | 即时支付 | 托管支付：escrow + evaluation |
| 典型流程 | 请求资源 → 返回 402 → 支付 → 获得访问 | 创建任务 → 锁定资金 → 提交结果 → 验收 → 放款/退款 |
| 适合场景 | API、数据、文章、RSS feed、模型调用、广告曝光 | 研究报告、内容创作、KOL 任务、Agent 外包任务 |
| 是否需要验收 | 通常不需要 | 需要 evaluator 验收 |
| 时间跨度 | 秒级 / 请求级 | 分钟、小时、天级任务 |
| 技术位置 | Web / HTTP 层 | Ethereum / EVM 智能合约层 |

---

## 更形象的理解

**x402 像“买门票”**：

> Agent 想访问一篇文章、一个 API、一个数据源，服务端返回 402 Payment Required。Agent 支付后，就可以访问。

**ERC-8183 像“发任务”**：

> 用户或 Agent 发布一个任务，先把预算锁进合约。服务方完成后提交结果，由 evaluator 验收。通过就付款，不通过或超时就退款。

---

## 在 Agent Commerce 中的位置

```text
┌────────────────────────────────────┐
│ ERC-8183：任务层 / 商业协作层       │
│ Job, escrow, evaluator, settlement │
└────────────────────────────────────┘
                  ↓
┌────────────────────────────────────┐
│ x402：访问层 / 微支付层             │
│ HTTP 402, API access, content paywall│
└────────────────────────────────────┘
```

**x402 管“每次访问怎么付费”。**  
**ERC-8183 管“一个任务怎么完成、验收、结算”。**

---

## 对 RSS / Agent Open Information Platform 的启发

如果你的产品是：

> 面向 Agent 的开放信息流、RSS 广告分发、付费内容访问、数据/API 订阅

那么早期 MVP 更适合优先看 **x402**。

例如：

```text
Agent 读取 RSS feed
↓
发现 sponsored event
↓
调用广告详情或内容 API
↓
通过 x402 支付 / 触发结算
```

如果你要做：

> 社区 sponsor KOL 解读事件、品牌方发布研究任务、Agent researcher marketplace

那么更适合引入 **ERC-8183**。

例如：

```text
社区发布任务
↓
资金进入 escrow
↓
KOL / Agent 提交内容
↓
Evaluator 验收
↓
通过后释放资金
```

---

## 最终判断

**x402 适合信息流里的即时消费。**  
**ERC-8183 适合信息流之上的任务市场。**

两者不是竞争关系，而是可以组合：

```text
x402 = Agent 获取资源的支付协议
ERC-8183 = Agent 完成交付的结算协议
```
