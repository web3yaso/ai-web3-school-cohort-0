# Task: AI Foundation Concepts

## 任务目标

用自己的话整理一组 AI 基础概念，为后续学习 Agent、workflow、AI coding 和工具调用建立共同语言。

## 完成情况

- 已整理 10 个基础概念。
- 每个概念都包含一句话解释、具体例子、常见误区或使用边界。
- 表达已按自己的理解改写，不直接复制 AI 输出。

## 关键笔记

### 1. LLM
一句话解释：LLM 是一种基于大量文本训练出来的语言模型，本质是根据上下文预测下一个 token 的概率分布，再通过对齐训练使输出更符合人类期望。
具体例子：我给它一段交易记录和"请总结风险点"的要求，它可以把原始信息整理成"金额异常、对手方未知、授权过大"等可读结论。
常见误区或边界：LLM 不是数据库，也不是事实保证器；它生成的内容看起来很顺，但仍然可能编造、漏掉关键条件，重要事实需要来源或工具验证。

### 2. Prompt
一句话解释：Prompt 是我给 AI 的任务说明，包含目标、背景、限制、输出格式和判断标准。
具体例子：比起只写"帮我分析这笔交易"，更好的 prompt 是"请用三段话说明这笔交易的资产变化、权限变化和主要风险，最后给出是否建议继续的理由"。
常见误区或边界：Prompt 不是魔法咒语，不能弥补缺失的数据、错误的上下文或不清楚的目标；写 prompt 的重点不是堆关键词，而是把任务边界讲清楚。

### 3. Context Window
一句话解释：Context window 是模型一次对话中能"看见"和处理的信息范围，有固定的 token 上限。
具体例子：如果我把课程要求、自己的笔记、代码片段和报错一起放进上下文，模型就能结合这些信息给出更贴近当前任务的建议。
常见误区或边界：上下文越长不一定越好；无关信息太多会稀释重点，模型也可能忽略前面较远的细节。更需要注意的是，超出 token 上限后，最早输入的内容会被截断丢失，而不只是被忽略，所以需要主动筛选和组织材料。

### 4. Workflow
一句话解释：Workflow 是把一个目标拆成一组有顺序、有输入输出、有检查点的固定步骤，与 Agent 的区别在于流程是预先设计好的，不会动态调整。
具体例子：做一笔链上 swap 的 workflow 可以是：读取用户目标、查余额、查报价、生成交易草稿、模拟交易、展示风险、等待确认、发送交易、记录结果。
常见误区或边界：Workflow 不等于"让 AI 自由发挥"；它更像流程设计，需要明确每一步什么时候继续、什么时候停止、失败后如何处理。

### 5. Agent
一句话解释：Agent 是能在一次任务周期内循环规划、调用工具、观察结果并调整下一步行动的 AI 系统；跨对话的记忆和状态持久化需要单独实现，不是 Agent 的默认能力。
具体例子：一个学习 Agent 可以读取我的学习计划，检查今天的任务，帮我生成练习草稿，再根据执行结果提醒我补充提交证据。
常见误区或边界：Agent 不等于完全自动化，也不等于一定安全；越能行动的 Agent 越需要权限控制、日志、回滚方案和人工确认。

### 6. Tool Use
一句话解释：Tool use 是让模型通过调用外部工具获取信息或执行动作，而不是只依赖自己生成文本——工具是外部的，查链上数据、访问网页、执行交易模拟等能力都不是模型本身自带的。
具体例子：模型可以调用 RPC 工具查询钱包余额，调用浏览器工具打开网页，调用交易模拟工具检查一笔交易是否会失败。
常见误区或边界：工具调用的结果不代表最终判断已经完成；工具可能失败、返回过期数据或被错误使用，所以需要校验输入、处理错误并记录调用过程。

### 7. AI Coding
一句话解释：AI coding 是把 AI 当作编程协作者，用它来读代码、写补丁、解释错误、生成测试和改进实现。
具体例子：我可以让 AI 根据报错定位函数，再让它补一个测试用例，最后运行测试确认修改是否真的解决问题。
常见误区或边界：AI coding 不是"自动交付正确代码"；生成代码必须经过阅读、测试和版本控制。尤其是涉及签名、私钥处理、授权逻辑的代码，必须逐行 review，不能只看测试通过。

### 8. Guardrails
一句话解释：Guardrails 是给 AI 系统设置的行为边界，用来限制它能做什么、不能做什么、什么时候必须停下来。
具体例子：链上 Agent 可以设置规则：不允许无限授权，超过 10 美元的交易必须人工确认，不支持的 chain id 直接拒绝执行。
常见误区或边界：Guardrails 不是一句"请注意安全"就够了；真正有用的边界需要落到代码、权限、策略检查、模拟和用户确认上。

### 9. Tracing
一句话解释：Tracing 是记录 AI 系统从输入到输出的关键过程，方便复盘它为什么这样判断或行动。
具体例子：一次 Agent 交易流程的 trace 可以记录用户目标、模型版本、调用过的工具、工具返回值、策略检查结果、用户确认和最终交易状态。
常见误区或边界：Tracing 不只是 debug 日志；它还关系到责任归因和安全审计，但也要注意不要把私钥、API key、敏感身份信息写进日志。

### 10. Human-in-the-loop
一句话解释：Human-in-the-loop 是在关键节点让人参与判断、确认或接管，而不是让系统一路自动执行到底。
具体例子：AI 可以准备交易草稿和风险摘要，但真正发送交易前必须让用户确认钱包弹窗和交易详情。
常见误区或边界：人工参与不应该只是形式上的"点一下确认"；系统要把风险、资产变化和不可逆后果讲清楚，否则人也无法做出有效判断。
