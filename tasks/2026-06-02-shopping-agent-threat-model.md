# 电商购物 Agent Wallet Threat Model

## 范围

本 threat model 面向一个服务于电商购物的 agent wallet。它可以帮助用户搜索商品、生成购物车、调用支付接口、发起链上付款、查询订单状态，并在任务级授权 Pact 内自动完成低风险付款。

核心安全目标：

- agent 只能执行购物相关动作；
- agent 不能获得长期、无限、不可撤销的钱包权限；
- agent 的每次链上动作都必须受预算、商户、合约、时间和操作类型约束；
- 超出授权边界时必须人工确认；
- 违规动作必须自动拒绝；
- 所有关键动作必须可审计、可追责、可恢复。

## 1. 资产

### 需要保护的资产

| 资产 | 说明 | 风险等级 |
| --- | --- | --- |
| Wallet 资金 | USDC、ETH、稳定币余额、购物预算资金 | 高 |
| Session key / agent key | agent 用于任务内自动执行的受限密钥 | 高 |
| Owner key | 用户或 Safe owner 的最终控制权 | 极高 |
| Recovery key | 用于恢复、撤销、替换 owner 的冷备权限 | 极高 |
| Merchant allowlist | 被允许收款的商户地址列表 | 高 |
| Pact 配置 | 预算、时间窗口、可调用合约、动作范围 | 高 |
| 订单信息 | 商品、价格、订单号、收货方式、发票信息 | 中到高 |
| 审计日志 | policy 决策、tx hash、人工确认记录 | 中到高 |

### 主要威胁

- agent key 泄露后被攻击者滥用；
- owner key 被误交给 agent 或被写入日志；
- recovery key 被热环境暴露；
- 商户白名单被恶意修改；
- Pact 被配置得过宽，变成长期权限；
- 审计日志泄露用户消费习惯或地址关系。

### 控制措施

- agent 只能持有短期 session key，不能持有 owner key；
- 资金放在 Safe 或智能账户中，而不是 agent 自己控制的 EOA；
- 每个 Pact 设置金额上限、时间上限、次数上限；
- merchant allowlist 更新必须人工确认；
- recovery key 不参与日常自动化；
- 日志中禁止记录私钥、助记词、完整收货地址和完整身份信息。

## 2. 权限

### 权限边界

购物 agent 的权限应该分为四类：

| 权限类型 | 示例 | 处理方式 |
| --- | --- | --- |
| 读取权限 | 查询余额、订单、商品价格、物流状态 | 可自动化 |
| 低风险执行权限 | 白名单商户、小额 USDC 付款 | Pact 内可自动化 |
| 中风险权限 | 新商户、超过阈值、失败重试、订阅付款 | 人工确认 |
| 高风险权限 | 修改 owner、修改 guard、提高预算、无限授权 | 默认禁止或多签确认 |

### 主要威胁

- agent 将一次购物授权扩大成长期付款权限；
- agent 对未知合约发起调用；
- agent 获取 token unlimited approval；
- agent 绕过单笔预算，拆分多笔付款；
- agent 修改白名单、预算或 policy；
- agent 通过工具调用间接触发未授权付款。

### 控制措施

- 默认 deny，只有明确 allowlist 的合约和函数可以调用；
- 单笔预算和滚动预算同时生效；
- 禁止 unlimited approval；
- 新商户首次付款必须人工确认；
- 修改 policy、budget、owner、recovery、guard 必须人工确认或多签；
- 每个 Pact 完成后自动 revoke；
- emergency freeze 可以立即暂停所有 agent 操作。

## 3. 数据

### 需要保护的数据

| 数据 | 示例 | 风险 |
| --- | --- | --- |
| 身份数据 | 姓名、邮箱、电话、地址 | 隐私泄露、钓鱼 |
| 购物数据 | 商品、价格、订单历史、偏好 | 用户画像泄露 |
| 支付数据 | token、金额、链、商户地址、tx hash | 链上身份关联 |
| 授权数据 | Pact、policy、allowlist | 被攻击者用于寻找绕过路径 |
| 日志数据 | policy 结果、失败原因、人工确认 | 泄露行为模式 |

### 主要威胁

- prompt、日志或工具响应中泄露完整个人信息；
- 恶意商户通过订单字段注入指令；
- agent 把用户地址、钱包地址和购物记录关联后外泄；
- 第三方 API 收集用户偏好和链上身份；
- 日志保留过久，扩大隐私风险。

### 控制措施

- 对工具上下文做最小披露，只传递完成任务必需的数据；
- 收货地址、电话、邮箱等敏感字段做脱敏存储；
- 不把完整订单信息写入链上 memo 或公开 metadata；
- 日志分级：安全审计需要保留，个人信息尽量哈希或截断；
- 对商户页面、商品描述、客服消息进行 prompt injection 检测；
- 明确日志保留周期和删除机制。

## 4. 工具调用

### 工具类型

| 工具 | 示例 | 风险 |
| --- | --- | --- |
| 浏览器工具 | 访问电商网站、读取商品页 | 页面注入、钓鱼、错误价格 |
| 支付工具 | x402、payment API、wallet SDK | 重复付款、错误收款方 |
| 钱包工具 | 签名、模拟、广播交易 | 越权交易、恶意 calldata |
| 数据工具 | 商品搜索、价格比较、库存查询 | 虚假结果、供应商偏见 |
| 通知工具 | 邮件、短信、IM | 泄露订单和地址 |

### 主要威胁

- 恶意网页诱导 agent 忽略原始指令；
- 工具返回伪造商户地址；
- 支付工具重复提交同一订单；
- 钱包工具广播未经模拟的交易；
- agent 把用户敏感信息发送给不必要的工具；
- 工具权限过宽，能调用与购物无关的 API。

### 控制措施

- 工具调用前做目的校验：这个调用是否服务于当前 Pact；
- 钱包广播前必须完成 calldata decode、地址校验、gas 估算和交易模拟；
- 每个支付请求必须绑定 order ID、merchant ID、amount、nonce；
- 使用幂等键防止重复付款；
- 工具权限最小化，不给购物 agent 通用 shell、通用签名或任意 HTTP 写权限；
- 工具输出不能直接变成交易，必须经过 policy engine 检查。

## 5. 外部依赖

### 关键依赖

| 外部依赖 | 示例 | 失败或攻击影响 |
| --- | --- | --- |
| 电商平台 | 商品、价格、库存、订单状态 | 买错商品、价格错误、订单失败 |
| 商户支付网关 | x402、结算 API、收款地址 | 错误收款、重复扣款 |
| 钱包基础设施 | Safe、ERC-4337 bundler、paymaster | 交易失败、延迟、gas 异常 |
| RPC 节点 | Base / Ethereum RPC | 状态过期、交易广播失败 |
| 价格服务 | USD/token 汇率 | 预算判断错误 |
| KYC / 风控服务 | 商户验证、风险评分 | 误拒绝或误放行 |
| 日志与监控 | 审计、告警、追踪 | 事后无法复盘 |

### 主要威胁

- RPC 返回过期状态，导致余额或 nonce 判断错误；
- bundler 或 paymaster 故障导致付款失败；
- 价格服务被操纵，预算判断失真；
- 商户支付 API 被劫持，替换收款地址；
- 电商页面显示价格和支付请求金额不一致；
- 第三方服务停机导致 agent 不断重试。

### 控制措施

- 关键链上状态使用多个 RPC 或可信 RPC 交叉验证；
- 付款金额以最终订单支付请求为准，并与页面价格做一致性检查；
- 汇率服务设置 staleness 检查和最大偏差阈值；
- 商户地址必须来自已验证 allowlist，而不是页面文本；
- 失败重试必须有限制，超过 2 次进入人工确认；
- 外部依赖异常时进入 safe mode，暂停自动付款。

## 6. 失败后果

### 失败类型与影响

| 失败类型 | 后果 | 严重度 |
| --- | --- | --- |
| 小额多付 | 用户损失小额资金 | 中 |
| 大额误付 | 资金不可逆损失 | 高 |
| 错误商户付款 | 付款给攻击者或错误地址 | 高 |
| 无限授权 | 未来余额可能被持续盗取 | 极高 |
| 私钥泄露 | 账户完全失控 | 极高 |
| 隐私泄露 | 身份、地址、消费记录暴露 | 高 |
| 重复下单 | 重复扣款、物流和退款成本 | 中 |
| 订单失败但链上已付款 | 需要人工退款和争议处理 | 高 |
| Policy 配置错误 | 系统性误放行或误拒绝 | 高 |

### 失败处理策略

- 小额失败：记录日志，限制自动重试次数；
- 大额失败：立即暂停 Pact，通知用户；
- 付款地址不一致：直接 deny，不进入自动重试；
- 交易失败：最多重试 2 次，之后人工确认；
- 检测到恶意合约或异常 calldata：freeze 当前 Pact；
- 检测到 agent key 泄露：revoke session key，移除 agent 权限，迁移剩余资金；
- 检测到 owner key 泄露：启动 Safe recovery 或资产迁移流程；
- 隐私泄露：删除非必要日志，轮换关联 token，通知用户。

## 7. 推荐安全策略

购物 agent wallet 的默认策略应当是：

- 只允许稳定币付款；
- 只允许付款到白名单商户；
- 只允许付款类函数；
- 单笔 100 USD 以下且商户已验证时可自动执行；
- 新商户、大额付款、approval、订阅、地址变更必须人工确认；
- 禁止 DEX、bridge、lending、staking、NFT mint、unlimited approval；
- 每个 Pact 最长 1 小时；
- 每个 Pact 默认只允许 1 次成功付款；
- 所有 allow、deny、require_approval 都进入审计日志；
- 用户可随时 freeze 或 revoke；
- 出现外部依赖异常时进入 safe mode。

一句话总结：购物 agent 的 threat model 不是只防“黑客偷钱”，还要防 agent 被诱导、工具返回错误、商户地址被替换、外部服务异常、隐私被关联，以及一次授权变成长期不可控权限。
